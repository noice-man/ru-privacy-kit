# RU Privacy Kit — 1.0.0-beta.12

**Тестовая сборка с исправлением процесса публикации.** WordPress ≥ 6.6, PHP ≥ 8.1. Интерфейс — русский. Распространение — ворд-пресс.рф, GPL-2.0-or-later.

## Установка

1. На тестовом WordPress откройте **Плагины → Добавить новый → Загрузить плагин** и выберите ZIP.
2. Активируйте «RU Privacy Kit». В верхней части админки появится приглашение к мастеру; также доступно меню **RU Privacy Kit**.
3. Пройдите восемь шагов: оператор, процессы обработки, сервисы и реестр cookies, режим аналитики, хранение, договор, дизайн и проверка.
4. На последнем шаге создайте **черновики** документов. Черновики можно собрать до заполнения всех обязательных полей, но публикация и включение баннера останутся заблокированы до их проверки. Проверьте их в редакторе WordPress, затем подтвердите и опубликуйте через **RU Privacy Kit → Документы**. До этого баннер выключен.
5. Проверьте Network/Cookies в DevTools на чистом профиле браузера; протестируйте отказ, согласие, изменение выбора и повторный визит. Проверьте мобильный экран.

**Внимание:** если на сайте уже установлены Яндекс Метрика, GA4, GTM или другие трекеры через тему/внешний плагин, их **необходимо отключить или отдельно настроить**. RU Privacy Kit контролирует только свои встроенные загрузчики Яндекс Метрики и GA4. Ни установка, ни выбор режима сами по себе не создают правового основания для обработки ПДн.

## В составе тестовой сборки

- 8-шаговый мастер, административное уведомление и сохранение прогресса.
- 5 видов cookie-баннера; светлая, тёмная, системная и наследуемая тема; ручные цвета и радиус; живой предпросмотр в админке.
- Режимы `strict` (Opt-in / Consent-first), `optout` (Analytics-first / Opt-out) и `advanced` (Google Advanced Consent Mode v2 при подтверждённом основании; Яндекс — strict).
- Предварительная блокировка управляемых тегов, управление аналитикой по выбору посетителя, повторный доступ к настройкам, перезагрузка после отзыва для остановки уже запущенных тегов.
- Cookie, Privacy, Terms, Public Offer: WordPress-страницы, Gutenberg-совместимый HTML, сначала черновики, ручное подтверждение, изменения с предварительным сравнением и использованием истории редакций WordPress.
- Встроенная совместимость с WordPress Consent API при его наличии; состояние «работает по иному основанию» **не передаётся** как положительное согласие.
- Необязательный локальный журнал минимизированных записей без IP и User-Agent, ежедневная уборка, лимит публичного эндпоинта.
- Клиент WPR Update Hub 1.1.3: обычные обновления через ворд-пресс.рф после публикации соответствующего релиза; добровольная телеметрия версий **выключена** до явного согласия в общих настройках SDK.

## Режимы аналитики

| Режим | До решения посетителя | После явного отказа |
|---|---|---|
| Строгий | Ни YM, ни GA4 от плагина не загружаются | Не загружаются |
| До отказа | Управляемая YM с индивидуальным подтверждением может работать; управляемый GA4 с подтверждением запускается только с Google Consent Mode `denied` и может передавать ограниченные запросы | Последующие запросы подавляются при обновлении страницы |
| Расширенный | Google с подтверждением может отправлять cookieless pings; YM остаётся strict | Google и YM не загружаются на следующей странице / после перезагрузки |

При неподтверждённом основании сервис остаётся в строгом режиме независимо от общего режима. Маркетинговые пиксели не загружаются плагином; их внешнее включение не контролируется в этой сборке.

## Состав и API

```
ru-privacy-kit.php
includes/{class-rupk-core.php,class-rupk-admin.php,class-rupk-front.php,class-rupk-documents.php}
assets/{css,js}/
vendor/wpr-updates-client.php
uninstall.php
```

Шорткод `[rupk_cookie_settings]` выводит кнопку повторного открытия настроек. JS события на `document`: `rupk:consent-ready`, `rupk:consent-changed`, `rupk:consent-revoked` с `detail.consent` и `detail.analyticsOperating`. JS `window.RUPK.hasConsent('analytics')` для интеграций, не подключаемых автоматически.

## Обязательные проверки перед промышленным внедрением

1. Проверить документы юридически и заполнить фактический реестр cookie с провайдером, целью, категорией и сроком хранения каждой технологии. Шаблоны не являются юридическим заключением.
2. Проверить при помощи DevTools отсутствие независимых внешних счётчиков, в том числе GTM, пикселей и встроенных SDK.
3. Проверить поведение внешних скриптов и кэширования, включая LiteSpeed, WP Rocket, Redis и CDN, а также WordPress Consent API совместимость. Зафиксировать различия между режимами.
4. Проверить GDPR/иностранные юридические режимы отдельно: пакет предназначен для российской аудитории.
5. Провести интеграционное тестирование на конкретных версиях WordPress, PHP, темах и используемых плагинах. Здесь выполнены синтаксические, модульные, браузерные layout-smoke тесты, но **не** комплексный тест реального WordPress-сайта.

## Что изменилось в beta.2

- Шаг 3: группы сервисов, условные настройки ID только выбранных счетчиков, сворачиваемое редактирование реестра cookie.
- Шаг 4: сведения о правовом основании только для выбранных сервисов и только при фактической необходимости; цель и данные представлены как *непроверенные заготовки*, которые нужно подтвердить.
- Шаг 8: единая модель проверок, разбивка на обязательные и рекомендательные, прямые ссылки на поля настройки.
- Изменение состава сервисов или реестра cookie снимает галочку о ранее проведённой проверке (при включённом JS); смена основания снимает его подтверждение.
- Сохранение ID выключенного сервиса и юридических сведений при переключении обратно в строгий режим.
- Генерация черновиков допустима с незаполненными полями; публикация по-прежнему защищена обязательной проверкой.
- Обновление beta.1 → beta.2 сохраняет опции в базе WordPress: удалять и переустанавливать плагин не требуется.

## Известные ограничения beta.2

- Не гарантируется блокирование трекеров, встроенных сторонними инструментами. Нет сетевого сканера и управления GTM, VK Pixel, iframe. Отображаются предупреждения о неконтролируемых сервисах.
- Генератор документов предоставляет редактируемые шаблоны, не окончательные юридические документы для произвольного бизнеса. Готовые тексты не должны публиковаться без проверки.
- Визуальная проверка дизайна выполнена на синтетической странице, а не на всех WordPress-темах.
- Журнал согласий, если включён, использует локальный nonce; на страницах с очень долгим HTML-кешем запись события может не сохраниться после истечения nonce. Выбор посетителя при этом сохраняется в cookie независимо от журнала.
- При отзыве аналитики после её запуска выполняется перезагрузка, чтобы установить ранние блокировки; невозможно отменить уже отправленные данные.
- Отдельные согласия в CF7/WPForms, deep-интеграции WooCommerce и полноценный scanner — следующие релизы. Автоматическая проверка государственных реестров не проводится.

## Изменения beta.3

- Раздел «Документы» показывает все блокирующие публикацию условия со ссылками «Исправить». Пока есть обязательные вопросы, кнопка публикации скрыта, но черновики остаются доступными.
- Ошибки подтверждения, отсутствующих страниц и изменений документов отображаются явным красным сообщением, а не зелёным уведомлением.
- Повторная проверка и подтверждение перезаписи показываются только для сгенерированных страниц с устаревшей редакцией — не для новых черновиков.
- Устаревшие черновики и опубликованные генерированные страницы обновляются только после явного согласия, с предупреждением о возможной замене ручных изменений.
- Публикация проверяет условия до изменения страниц, исключая частичную публикацию при известных ошибках конфигурации.

Подтверждения не сохраняются в виде бессрочной галочки: после редактирования текстов либо отказа публикации администратор проверяет и подтверждает документы заново.

## Beta.6 — автоматическая публикация

Последний шаг мастера теперь выполняет проверку и, после явного подтверждения администратора, создаёт или обновляет юридические страницы, назначает страницу политики персональных данных в настройках WordPress и включает баннер. Существующие авторские страницы не перезаписываются, ручные правки в созданных плагином документах требуют отдельного подтверждения. Стандартный текст WordPress с фразой «Предлагаемый текст» заменяется только с разрешения пользователя.

## Public Beta 1.0.0-beta.12

- «Счётчики и пиксели»: установка кода Яндекс Метрики, GA4, SberAds и рекламного пикселя VK через ID в админке.

## Новое в 1.0.0-beta.12

- Профиль оператора: экспорт и двухэтапный импорт JSON с предпросмотром изменений. Не переносит настройки конкретного сайта или счётчики. По умолчанию не экспортирует домашний адрес и email поддержки.
- Визуальный вывод созданных плагином юридических страниц теперь динамический: изменённые реквизиты и иные сведения отображаются из текущих настроек без перепубликации; вручную изменённые страницы остаются неизменными.
- Для физлица и ИП адрес не публикуется по умолчанию. Включается отдельно в мастере. Для коммерческих сайтов проверяйте требования к раскрытию сведений о продавце или исполнителе.
- Не сбрасывает баннер и пользовательские согласия при обычном изменении сведений оператора. Изменения сервисов/режима аналитики по-прежнему проходят проверку и защитную деактивацию до подтверждения.
- Обычные автоматические обновления данных больше не показывают предупреждения о необходимости перезаписи черновиков. Ручные правки к документам защищены.
